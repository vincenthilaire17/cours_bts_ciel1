Cahier des charges fonctionnel :

  1. Phase d’Armement : Le joueur règle la difficulté via le potentiomètre. Un appui sur le bouton arme le système (bip d’avertissement).
  2. Attente Aléatoire & Anti-Triche : Le système patiente un délai imprévisible (entre 2 et 5 secondes). Si le joueur appuie pendant cette attente (anticipation/triche), le buzzer déclenche une alarme stridente, la LED rouge clignote et la manche est annulée.
  3. Le “TOP” Réflexe : La LED verte s’allume subitement et un bip aigu retentit. Le chronomètre démarre instantanément à la milliseconde près.
  4. Acquisition du Réflexe : Dès que le joueur appuie sur le bouton :
    • Le temps de réaction est calculé et affiché dans la console Thonny (REPL).
    • Les LEDs indiquent le niveau de performance (Verte = Ninja, Jaune = Acceptable, Rouge = Trop lent).
  5. Session de 5 Manches & Bilan : Au bout de 5 manches, le système affiche les statistiques complètes de la session (meilleur temps, temps moyen, nombre de pénalités pour triche).

PARTIE 1 : En finir avec le blocage — Chronométrage haute précision (45 min)

Problématique

Jusqu’ici, vous utilisiez time.sleep(secondes) pour temporiser. Cependant, time.sleep() fige complètement le microcontrôleur : pendant une pause, le processeur est aveugle : il ne lit aucun bouton et ne mesure rien.

Pour mesurer un temps en temps réel, MicroPython propose deux fonctions matérielles : * t0 = time.ticks_ms() : relève la valeur d’un compteur interne en millisecondes. * delta = time.ticks_diff(t1, t0) : calcule avec précision la durée écoulée entre deux relevés t0 et t1 (gérant automatiquement les dépassements de compteur 32 bits).

PARTIE 2 : L’Aléatoire & Le Système Anti-Triche (45 min)

Pour rendre le test équitable, le délai d’attente avant le signal doit être imprévisible. De plus, nous devons sanctionner les joueurs qui appuient trop tôt !

Le module random

En Python, random.uniform(a, b) renvoie un nombre flottant aléatoire compris entre a et b. Exemple : delai = random.uniform(2.0, 5.0) génère une durée aléatoire entre 2 et 5 secondes.

Exercice 2.1 — Détection de faux départ

Pour surveiller le bouton pendant l’attente sans bloquer le processeur, nous découpons l’attente en millisecondes :

import random

def attendre_depart_avec_surveillance(duree_secondes):
    """
    Attend la durée spécifiée tout en surveillant le bouton.
    Renvoie True si le joueur a triché (appui prématuré), False sinon.
    """
    duree_ms = int(duree_secondes * 1000)
    t_debut = time.ticks_ms()
    
    while time.ticks_diff(time.ticks_ms(), t_debut) < duree_ms:
        if bouton.value() == 1:
            return True  # Faux départ détecté !
        time.sleep_ms(1)  # Petite pause de 1 ms pour stabiliser
    
    return False  # Aucun faux départ

PARTIE 4 : Architecture Avancée — Machine à États Finis (FSM) & Potentiomètre (45 min)

4.1 Pourquoi une Machine à États Finis ? (En finir avec le code “Spaghetti”)

Dans les parties 1, 2 et 3, vous avez développé des briques fonctionnelles séparées. Si vous tentez de les assembler naïvement en empilant des boucles while et des conditions booléennes (en_train_de_jouer = True, a_triche = False, attente = True…), vous créerez ce que les développeurs appellent du code spaghetti : un programme rigide, difficile à déboguer et sujet à des blocages imprévus.

La méthode professionnelle en informatique embarquée consiste à modéliser le comportement du système à l’aide d’une Machine à États Finis (FSM - Finite State Machine) : * Un état unique à la fois : Le système se trouve à chaque instant dans un état précis et exclusif (VEILLE, ATTENTE, CHRONO, TRICHE…). * Une boucle maîtresse limpide : La boucle while True: principale aiguille simplement l’exécution vers le bloc de l’état actif (if etat == ... elif etat == ...). * Deux règles d’or par état : 1. Exécuter l’action liée à l’état (ex: allumer une LED, déclencher un son). 2. Vérifier la condition d’événement pour basculer vers un nouvel état (transition).

                      +----------------------------------------------------+
                      |                                                    |
                      v                                                    |
                [ETAT_VEILLE] ---> (Appui Bouton) ---> [ETAT_ARMEMENT]     |
                                                             |             |
                                                             v             |
                                                [ETAT_ATTENTE_ALEATOIRE]   |
                                                  |              |         |
                                   (Appui anticipé|              | (Délai) |
                                       = Triche)  v              v         |
                                           [ETAT_TRICHE]   [ETAT_CHRONO]   |
                                                  |              |         |
                                                  |              | (Appui) |
                                                  v              v         |
                                                [ETAT_EVALUATION] ---------+

4.3 Le Potentiomètre : Conversion mathématique de la difficulté

Le potentiomètre sur GP26 (ADC0) fournit une mesure brute comprise entre 0 (0V) et 65535 (3.3V). Nous voulons transformer cette valeur en un seuil de temps limite toléré compris entre 300 ms (mode difficile / athlète) et 900 ms (mode facile / débutant) :

$$\text{seuil\_max\_ms} = 300 + \left( \frac{\text{valeur\_adc}}{65535} \times 600 \right)$$

  • Si le potentiomètre est à gauche (valeur_adc = 0) : 300 + 0 = 300 ms.
  • Si le potentiomètre est au milieu (valeur_adc = 32768) : 300 + 300 = 600 ms.
  • Si le potentiomètre est à droite (valeur_adc = 65535) : 300 + 600 = 900 ms.

Si le joueur ne réagit pas avant ce temps limite, la manche est considérée comme perdue (trop lent !).
