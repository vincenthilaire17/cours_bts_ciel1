1. Pourquoi la Machine à États Finis ? (En finir avec le code Spaghetti)

Dans les systèmes embarqués élémentaires, les étudiants débutent souvent en enchaînant des instructions séquentielles bloquantes (ex: time.sleep(3) ou delay(3000)) et en multipliant des drapeaux booléens (en_cours = True, bouton_vu = False, alarme_active = True...).

❌ Approche Linéaire Bloquante ("Spaghetti")

  • CPU figé : Pendant un sleep(), le microcontrôleur est incapable de lire un capteur d'arrêt d'urgence ou un bouton.
  • Explosion combinatoire : 5 variables booléennes créent 25 = 32 combinaisons d'états souvent imprévisibles et incontrôlées.
  • Débogage cauchemardesque : Impossibilité de savoir précisément où en est l'exécution en cas de bug.

✅ Approche FSM (Machine à États Finis)

  • Unicité de l'état : Le système se trouve à chaque instant dans un état précis, unique et exclusif (ex: VEILLE, CHRONO).
  • Exécution non bloquante : La boucle maîtresse s'exécute à haute cadence (ex: toutes les 5 ms).
  • Clarté industrielle : Correspondance directe 1:1 entre le diagramme théorique et le code source.

2. Notions Fondamentales & Vocabulaire Technique

Une Machine à États Finis (en anglais Finite State Machine ou FSM) est un modèle mathématique composé de 4 piliers essentiels :

Concept Définition Formelle Exemple Système Embarqué
État (State) Situation stable et identifiable dans laquelle se trouve le système pendant une durée donnée. L'état détermine le comportement présent. ETAT_ATTENTE : La LED jaune est allumée, le chronomètre est armé.
Événement (Event / Input) Stimulus d'entrée (externe ou interne) susceptible de provoquer une réaction du système. Front montant sur le bouton poussoir (bouton.value() == 1) ou fin de temporisation.
Condition de Garde Condition booléenne supplémentaire requise pour autoriser la transition lors de la survenue de l'événement. [temps_ecoule < seuil_max] ou [temperature > 50°C].
Transition Passage instantané et exclusif d'un état source à un état cible, validé par un événement vérifiant la garde. Basculement de ETAT_VEILLE vers ETAT_ARMEMENT.
Action Opération exécutée par le microcontrôleur. Elle peut être liée à l'état ou à la transition. Émettre un bip sonore, allumer une LED, incrémenter un compteur.

5. Implémentation Logicielle en MicroPython

Le patron de conception canonique d'une FSM en MicroPython repose sur une boucle while True: principale et une aiguille if / elif cadencée de manière régulière :

# --- CONSTANTES D'ÉTATS (Lisibilité & Maintenance) ---
ETAT_VEILLE            = 0
ETAT_ARMEMENT          = 1
ETAT_ATTENTE_ALEATOIRE = 2
ETAT_CHRONO_REACTION   = 3
ETAT_TRICHE            = 4

# Variable d'état initiale
etat = ETAT_VEILLE

# --- BOUCLE MAÎTRESSE NON-BLOQUANTE ---
while True:
    # 1. ÉTAT VEILLE : Surveillance de l'entrée
    if etat == ETAT_VEILLE:
        led_jaune.value(1)
        if bouton.value() == 1:
            attendre_relachement()
            led_jaune.value(0)
            etat = ETAT_ARMEMENT  # <-- Transition

    # 2. ÉTAT ARMEMENT : Initialisation temporelle
    elif etat == ETAT_ARMEMENT:
        bip(440, 150)
        delai_ms = random_intervalle(2000, 5000)
        t_debut = time.ticks_ms()
        etat = ETAT_ATTENTE_ALEATOIRE  # <-- Transition immédiate

    # 3. ÉTAT ATTENTE NON-BLOQUANTE & DÉTECTION ÉVÉNEMENTS
    elif etat == ETAT_ATTENTE_ALEATOIRE:
        if bouton.value() == 1:
            # Événement Faux Départ !
            attendre_relachement()
            etat = ETAT_TRICHE     # <-- Transition d'erreur
        elif time.ticks_diff(time.ticks_ms(), t_debut) >= delai_ms:
            # Événement Délai expiré !
            etat = ETAT_CHRONO_REACTION

    # 4. ÉTAT TRICHE : Traitement de la sanction
    elif etat == ETAT_TRICHE:
        alerte_sonore_stridente()
        etat = ETAT_VEILLE

    time.sleep_ms(5)  # Cadencement de la boucle (Échantillonnage 200 Hz)

6. Les 5 Règles d'Or du Développeur Embarqué

Règle 1 : Nommer les états sous forme de constantes parlantes Bannir les nombres magiques (ex: etat = 2). Utiliser des identifiants explicites : ETAT_ATTENTE, ETAT_ALARME.
Règle 2 : Proscrire les attentes bloquantes (time.sleep) dans la boucle active Un sleep(2) bloque le traitement des interruptions et désactive la scrutation des boutons. Utiliser le couple time.ticks_ms() / time.ticks_diff().
Règle 3 : Assurer l'anti-rebond matériel ou logiciel Un bouton mécanique rebondit pendant 5 à 20 ms. Veillez à toujours attendre le relâchement ou utiliser une fonction de débouçage pour ne pas franchir deux transitions d'affilée.
Règle 4 : Toujours prévoir un état de repli ou de sécurité (Failsafe) En cas de valeur imprévue ou d'erreur capteur, le bloc else: doit ramener le système vers un état de sécurité connu (ex: ETAT_VEILLE).
Règle 5 : Écrire la table de transition avant de coder Poser sur papier la matrice (État Actuel × Événement ➔ Nouvel État + Actions) avant d'écrire la moindre ligne de code permet d'éliminer 90% des bugs d'architecture.
