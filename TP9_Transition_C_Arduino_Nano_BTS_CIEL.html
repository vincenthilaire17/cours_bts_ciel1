ÉTAPE 0 : L'Arduino Nano (ATmega328P), Environnement & Schéma d'Architecture 20 min

0.1 De l'Interprété au Compilé : Pourquoi Passer du Python au Langage C en BTS CIEL ?

Jusqu'à présent (TP 3 à TP 8), vous programmiez le Raspberry Pi Pico en MicroPython : vos scripts .py étaient interprétés à la volée par une machine virtuelle embarquée. Ce fonctionnement offre une grande souplesse, mais au prix d'une consommation mémoire colossale (plusieurs centaines de kilo-octets) et d'un temps d'exécution imprévisible.
Dans l'industrie des objets communicants et de l'électronique de puissance (épreuves E4, E5 et E6 du BTS CIEL), la majorité des microcontrôleurs cibles sont programmés en langage C / C++ natif : le code est traduit directement en instructions binaires machine par le compilateur (avr-gcc), offrant une vitesse d'exécution maximale, un déterminisme temporel strict et la capacité de tourner sur des puces économiques ne disposant que de 2048 octets de mémoire vive !

Critère technologique MicroPython sur Raspberry Pi Pico (RP2040) Langage C sur Arduino Nano (ATmega328P)
Mode d'exécution Interprété (Bytecode exécuté par la VM Python) Compilé natif (Code machine binaire direct)
Typage des variables Dynamique (le type dépend de la valeur à l'instant t) Statique strict (le type est figé à la compilation)
Cœur & Fréquence Dual-Core ARM Cortex-M0+ (32 bits) — 133 MHz AVR RISC 8 bits — 16 MHz
Tension logique E/S 3,3 V (Non tolérant 5 V !) 5,0 V (Idéal pour piloter directement la puissance !)
Mémoire SRAM (RAM) 264 Ko (Très spacieux) 2 Ko (2048 octets seulement !) → Rigueur absolue requise !
Mémoire Flash (Code) 2 Mo externe SPI 32 Ko intégrée

PARTIE 1 : Typage Statique Strict, Format des Variables, sizeof() & Débordement Binaire 1h00

1.1 Le Choc du Typage Statique : Python vs C

En Python, les variables n'ont pas de type déclaré : c'est la valeur qui porte le type, et une même variable peut changer de type à tout instant (x = 10 puis x = "Capteur OK"). En C, le type de chaque variable doit être impérativement spécifié avant la compilation. Le compilateur réserve alors un nombre exact d'octets en mémoire vive (SRAM) qui ne pourra jamais changer.

PARTIE 2 : Structures de Contrôle : if/else, switch/case, while & for 55 min

2.1 Syntaxe Comparée des Structures Algorithmiques : Python ↔ C Arduino

En Python, la structure des blocs repose sur l'indentation invisible (tabulations / espaces) et les deux-points :. En C, l'indentation n'est que visuelle pour le programmeur : le compilateur délimite strictement chaque bloc d'instructions par des accolades ouvrantes et fermantes { }, chaque instruction simple se termine obligatoirement par un point-virgule ;, et toute condition doit être placée entre parenthèses ( ).

🐍 Syntaxe MicroPython (RP2040)

# Conditionnelle à plusieurs branches
if tension > 3.0:
    relais.value(1)
elif tension > 1.5:
    relais.value(0)
else:
    alarme.value(1)

# Boucle bornée (range)
for i in range(0, 10, 2):
    print(i)

# Boucle conditionnelle
while en_marche:
    mesurer()

⚙️ Syntaxe Langage C / Arduino (ATmega328P)

// Conditionnelle à plusieurs branches
if (tension > 3.0f) {
    digitalWrite(PIN_RELAIS, HIGH);
} else if (tension > 1.5f) {
    digitalWrite(PIN_RELAIS, LOW);
} else {
    digitalWrite(PIN_ALARME, HIGH);
}

// Boucle bornée (initialisation; condition; incrément)
for (uint8_t i = 0; i < 10; i += 2) {
    Serial.println(i);
}

// Boucle conditionnelle
while (enMarche) {
    mesurer();
}

2.2 La Sélection Multiple : L'Instruction switch / case

En C embarqué, lorsque vous testez une variable entière ou énumérée prenant plusieurs états discrets, vous devez privilégier l'instruction switch / case plutôt qu'une cascade de if / else if : le compilateur avr-gcc génère alors une table de saut direct en mémoire Flash (Jump Table), exécutant la transition en un seul cycle d'horloge (62,5 ns) sans évaluer séquentiellement chaque condition !

PARTIE 3 : Fonctions en C : Types Renvoyés & Passage par Référence & 50 min

3.1 Anatomie d'une Fonction C vs Fonction Python

En Python, une fonction commence par def nom(arg1, arg2): sans préciser ce qu'elle reçoit ni ce qu'elle renvoie. En langage C, le type renvoyé par la fonction doit obligatoirement précéder son nom, et chaque paramètre d'entrée doit posséder son type strict : 

// Prototype canonique en langage C
type_renvoye nomFonction(type_param1 param1, type_param2 param2) {
    // Corps de la fonction
    return valeur_du_bon_type;
}

3.2 Passage par Valeur vs Passage par Référence (L'Opérateur &)

C'est la différence la plus fondamentale entre le C et le Python :
• Par valeur (par défaut) : Le compilateur duplique la variable dans la pile (Stack). La fonction travaille sur une copie : toute modification apportée au paramètre est perdue dès la sortie de la fonction !
• Par référence (opérateur &) : Le compilateur ne copie pas la donnée, il transmet l'adresse mémoire de la variable d'origine. La fonction modifie directement la variable de l'appelant, sans consommer d'octets supplémentaires en SRAM !

PARTIE 4 : Communication Série Bidirectionnelle (UART), Formats & Parsing de Commandes 55 min

4.1 L'UART Matériel de l'ATmega328P (Broches D0/RX et D1/TX)

L'Arduino Nano communique avec le PC via son interface série asynchrone (UART) cadencée à 115 200 bauds (8 bits de données, 1 bit de stop, sans parité : format 8N1). Les octets reçus du PC sont automatiquement empilés en tâche de fond dans un buffer circulaire matériel de 64 octets géré par interruption.

4.2 Affichage Multi-Format avec Serial.print()

En C Arduino, la méthode Serial.print() accepte un second paramètre optionnel définissant la base de conversion numérique :

  • Serial.print(valeur, DEC); : Affiche en décimal (par défaut, ex: 181).
  • Serial.print(valeur, HEX); : Affiche en hexadécimal (très utile en protocole bus, ex: B5).
  • Serial.print(valeur, BIN); : Affiche en binaire direct (ex: 10110101).
  • Serial.print(tension, 3); : Pour un nombre flottant, impose 3 décimales après la virgule !
